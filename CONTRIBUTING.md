# Contributing

Open an issue with a concrete marketing job, business model, expected deliverable and minimal synthetic evidence. Propose changes through a pull request. Keep instructions focused, source-aware and scoped to actual user authority. Preserve existing user work and business isolation. Never add credentials, private contact lists or raw transcripts.

Keep discoverable skill/agent/command inventory within the documented release profile. Do not add runtime servers, MCP, hooks, installers or dependencies to this instruction-based package without an explicit architecture decision. Review provenance, factual claims, calculation units and external-action states. Update documentation and relevant examples for behavior changes; demonstrate useful outcomes rather than broad performance promises.
