# Directory review notes

Prepared 2026-10-28 for v0.4.5. The owner approved the final display name and description on 2026-10-28. This document is not an Anthropic certification, legal opinion or promise of acceptance.

## Implemented controls

- Owner-approved descriptive display name, concrete marketing tasks, factual component counts and valid public support/privacy links. Installation IDs are preserved.
- No bundled runtime, hooks, installers, credential store, MCP server or automatic collection. External CLI procedures require an appropriate permitted destination and exact user scope; otherwise draft/import/handoff only.
- No AI video/audio/voice or general image generation. Creative work produces copy, design briefs, scripts, storyboards or permitted design-only visual aids.
- No Claude memory/history extraction, conversation-derived user profiles, automatic preference persistence or hidden telemetry. Uploaded/user-file extraction is disabled, including explicitly selected files. Continuation uses state supplied inline; legacy file routes are manual handoff formats only.
- All 38 Actor identities are freshly observed as public and publisher-owned. Acquisition remains separately gated: 16 import-only, 22 access-review-required. Runtime results, current schemas, pricing and source permission are not established by listing checks.
- Personal data minimization, suppression preservation, claim evidence and unknown-outcome reconciliation apply across the workflow.

## Review and publication gaps

Automated checks cannot establish every legal right, account permission, service retention practice or host behavior. Provider/privacy and endpoint-admission evidence must be verified before live use. No charged Actor run, outreach, publication, scheduler activation or media generation was used for validation.

The original Claude organization already submitted this repository folder. A different organization cannot independently claim it through a rename or new draft. Resolve ownership with Anthropic's supported process; do not delete the old listing or fork the repository to evade that restriction. The alternate organization also needs its own GitHub push-access verification. Terms/compliance acknowledgements require the authorized owner's action-time review.
