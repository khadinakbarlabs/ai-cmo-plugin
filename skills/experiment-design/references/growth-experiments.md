# Growth Hacking and Growth Systems

Apply the [shared operating contract](../../cmo/references/operating-contract.md). Use [Business Model Strategy](../../business-model-strategy/SKILL.md) to adapt goals and economics when context is missing.

Apply this reference through the owning skill; it is not a separate installed skill.

## Workflow

1. Identify the model-specific bottleneck and repeat-value event from the funnel/cohort evidence; do not assume every business has a SaaS signup funnel.
2. Map repeatable mechanisms: useful free resources, product-led sharing, onboarding, partnerships, integrations, owned audiences or lifecycle triggers; state the causal hypothesis.
3. Rank experiments by impact, evidence confidence, effort, cash cost and dependency with visible components; avoid invented traffic forecasts.
4. Design the smallest measurable experiment with audience, variants, success threshold, guardrails, duration/stop rule, owner and rollback using experiment-design for analysis.
5. Produce the actual first assets and implementation brief using current available tools; require authority for charged jobs, product changes and external actions.
6. Review cohort quality, retention, margin and incrementality before scaling. Do not propose spam, fake reviews/engagement, deceptive scarcity, scraped-user blasting or circumvention as growth tactics.

## Deliverable

Loop map, scored experiment backlog, first experiment pack and scale/iterate/stop decision criteria.

Read the [working reference](growth-experiments-workflow.md) for relevant variants, fields and handoffs. For connected work, use [CLI capability checks](../../cli-integrations/references/tool-capabilities.md); no CLI or MCP is bundled.
