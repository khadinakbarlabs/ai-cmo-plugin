# Lifecycle Marketing working reference

## Output contract

Journey map, message sequence, trigger/suppression rules and implementation/test brief.

Record the business/campaign ID, source dates and input scope. Include the useful artifact plus evidence, unavailable fields, decision and next owner. Treat an estimated outcome as a hypothesis until measured.

## Quality checks

- Does the output answer the requested customer/business job?
- Can another person verify the important facts from the retained evidence?
- Are prerequisites and actual tool capabilities distinguished from completed actions?
- Are unknown metrics marked and recommendations tied to a test or evidence?
- Is the next handoff concrete and editable?

## Recovery

For missing tools or accounts, produce the useful draft/import-based result and identify the specific missing capability. For empty data, retain collection scope and explain the absence rather than inventing a finding. For partial results, mark the missing portion and avoid extrapolating to the whole market.

## Journey implementation schema

For each stage specify entry event, segment, delay, message/asset, conversion/exit event, suppression, frequency conflict and owner. Distinguish product events available today from instrumentation to add. Cart recovery requires cart/consent signals; churn recommendations need cohort/renewal context. Test the journey against dummy users before deploying authorized provider changes. Include appropriate failure handoff when an event is missing rather than silently enabling a broken sequence.

## Covered variants

- Lifecycle segmentation
- Welcome and nurture sequences
- Onboarding and activation email
- Abandoned cart recovery
- Retention and winback
- CRM workflow and handoff design

## Optional external CLI

Follow the [verified external CLI procedure](../../cli-integrations/references/resend-cli.md) when the task needs connected execution. Use existing accounts and the shared authority/cost contract.

## Channels and business-specific lifecycle

Plan email, SMS/messaging, push/in-app or supported offline follow-up according to actual audience permission, preference, model and provider capability. Respect cross-channel frequency and suppression. Marketing consent and a transactional service message are distinct purposes. Recurring contracts, repeat purchases, renewals, rebooking, repeat donations and distributor reorders need different triggers; do not label them all SaaS activation. An available email CLI does not establish SMS/WhatsApp/push execution.
