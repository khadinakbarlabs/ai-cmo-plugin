# Company-first lead imports and provenance

First useful result: inspect the supplied file, define account fit from existing business context, and deliver an editable qualified/unknown/excluded account sheet plus a preservation mapping and one next action. No login, paid sample, contact search or mandatory capture funnel is needed. Do not send messages or treat possession of an email as permission to contact.

1. Inspect file type, headers, row/size scope and business identity without dumping private rows. Missing file → PROJECT_MISSING; malformed rows or absent required identity → INPUT_INVALID. Ask only for material fit/exclusion rules unavailable in context. Keep unknown qualifications unknown. Define mandatory fit criteria from the supplied business context before scoring. Every mandatory criterion needs supporting evidence for qualified status; a repair-industry match does not establish independent repair-shop status. If independence or any other mandatory criterion is unverified, classification is unknown with the known category match recorded separately. A caveat beside a qualified label does not repair premature qualification.
2. Agree account grain (company, branch/location or contact). Match source/CRM account IDs within their namespace first. A reviewed domain match may help, but a domain alone cannot merge branches, franchisees or same-name businesses. Rows without a stable reviewed identity receive an operation-scoped ID and remain unmatched for review. Never join by row number after deduplication.
3. Produce `accounts.csv` with account_id, grain, company_name, domain, qualification (qualified/unknown/excluded), evidence/source reference, observed_at, conflict, owner and next_action. For do_not_contact=true, next_action must be an internal evidence-review or suppression-maintenance task; never propose an invitation, send or conditional outreach as the next action. Qualification needs actual fit evidence; an email/domain is not an opportunity or validated address. Do not invent acceptance, deliverability or consent.
4. Preserve authorized provider/CRM fields in `field-map.json` joined by account_id. Include every source namespace/record ID, aliases, exact relevant field values and field-level source references, including CRM owner/stage, suppression/do-not-contact state, branch IDs and source dates. Retain original import securely when authorized; do not put customer data in plugin source or shared examples. Never copy secrets, passwords, tokens or session material into either artifact; quarantine/redact them and report that exclusion.
5. Keep conflicting field values with their source IDs; do not let a newer blank erase a known value. Preserve all exclusion/suppression evidence when merging; never loosen a restriction silently. Unmatched/ambiguous rows stay in a separate review table with stable source IDs. Exported enrichment is an optional later stage, not a prerequisite for company qualification.
6. Reconcile raw rows = retained source records + quarantined/review records; canonical account count can be smaller after deduplication. Explain excluded and merged counts separately. Validate that every mapping account_id exists in the account sheet, every retained source ID is represented, and no approved CRM/suppression/branch field was lost. Show coverage limits and one next action, not fabricated zero demand.

For paged run imports, use [Apify paging](../../apify-research/references/apify-cli.md), retaining raw source offsets before filtering/deduplication. Use an [operation receipt](../../cmo/references/operation-contract.md) for partial work. The task board keeps campaign status; the receipt keeps run/readback/checkpoint detail.

Example (fictional): source CRM account `crm:AC-17` and export company `export:co-9` match the reviewed same legal company. Join both under `account:AC-17`, preserving CRM owner, `do_not_contact=true`, source URLs and conflicting stage values. An unrelated branch `crm:AC-18` sharing the website remains separate. Raw source records need no personal contact details to qualify the accounts. “Ready for outreach” must never override the retained suppression.

The package provides instructions and schemas, not an automatic normalizer or collector. Use available file tools for local imports and the user's official installed CLI for remote reads. If the host cannot write files, return complete tables/mapping inline and mark persistence unsaved.
