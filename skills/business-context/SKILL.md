# Business Context

Apply the [shared operating contract](../cmo/references/operating-contract.md) for evidence, local context and action scope.

## Workflow

1. Choose a user-owned workspace and business; do not mix account data between clients.
2. From the current inline brief, identify model, industry, stage, stakeholders, offering/pricing, geography, sales cycle, repeat-value event, economics, team/capacity, conversion paths and existing assets; record URLs and observation dates.
3. Separate confirmed project facts, supplied brand requirements, hypotheses and unanswered questions. Do not infer or retain personal profiles. Ask only for essential unavailable constraints.
4. When requested, write business, brand and goals files; otherwise return a complete brief inline; identify prohibited claims, geography, budget and primary conversion.
5. Retain decisions and freshness dates; update rather than blindly replacing established context.

## Deliverable

Editable business.md, brand.md, goals-and-constraints.md and capability summary.

Use the [working reference](references/workflow.md) for covered variants, output fields and quality checks.

## Rich context and user feedback

Use [context protocol](../cmo/references/context-protocol.md) for fact provenance, freshness, preference updates, contradictions, client isolation and bounded session capsules. Reuse current inline project facts before asking questions; do not query files, history or memory. Optional [artifact feedback](../cmo/references/feedback-loop.md) corrects the requested output or explicitly requested project document; no global telemetry or silent uploads.
