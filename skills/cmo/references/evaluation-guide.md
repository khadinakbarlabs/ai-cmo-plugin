# Measure usefulness before claiming improvement

Evaluate outcomes, not message volume. The plugin can structure evaluation through local fixtures, actual host runs and user-owned records; it has no automatic cross-user analytics service.

Use a matched no-plugin baseline and AI CMO on the same supplied business materials, model/host, tool access, cost/call/time budget and output request. Use separate clean sessions, alternate order and judge outputs against the same acceptance criteria. Label results from a small sample as exploratory. Include local services, long-cycle B2B, ecommerce, nonprofit and a custom business where practical; the sample cannot certify every industry.

| Scenario | Acceptance | Evidence to keep |
| --- | --- | --- |
| First useful task | Correct business outcome and an actual usable first asset | Output, elapsed time, claim check, user's acceptance/edit request |
| Continue a campaign | Reuse completed assets and preserve task/decision fields | Original/updated board, no duplicate work, observed persistence |
| Context correction | Apply a specific preference/fact without spreading it across clients | Before/after output and source-linked changed context |
| Feedback loop | Respect declined feedback; resolve real corrections with an artifact | Minimal record, corrected output, unresolved items |
| Performance report | Correct ratios/percentages/units, explicit missing data, clear next decision | Inputs, calculation trail, visual output/readability |
| Recurring review | Actual host registration/readback, bounded run, quiet unchanged monitoring and verified cancellation | Scheduler receipts, report and scope; otherwise draft/unavailable |

Score each output for business fit, factual accuracy, asset completeness, actionability and user effort. Record time to accepted useful output, edits needed, cost where observed, completed requested tasks, blockers and return to a relevant next step. Satisfaction and repeat usage require real user evidence; no reply does not mean approval. Do not derive revenue lift or causality from artifact quality.

An improvement claim must name the metric, baseline, sample, dates and limits. A 10× time saving in one task would require observed accepted-output time at most one tenth of the baseline under comparable conditions; it would not prove 10× marketing performance or universal intelligence. Until actual comparison runs exist, describe capabilities and tested boundaries only. Live paid collection, sends and schedules need the specific evaluation authority and scope.
