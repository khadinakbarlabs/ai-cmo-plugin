# Outcome-driven learning loop

Load only the guides needed for the current job. This is instruction-based continuity using user-owned files and host capabilities; no persistent executor or automatic telemetry is installed.

## Understand → recommend → produce → review → measure → learn

1. Use [context protocol](context-protocol.md) to select the business and current goal. Start from existing context and recent session/task state. Resolve material conflicts and stale evidence before a consequential recommendation.
2. Use [decision policy](decision-policy.md) to recommend one next useful action with reason, confidence, prerequisites, effort and measurable success. "Instinct" means an explainable working hypothesis, never an invented fact. Adapt to the user's capacity, buying cycle, voice and preferred level of detail.
3. Use the relevant skill and [agentic workflow](agentic-workflow.md) to deliver an actual asset, research result or decision. Use bounded specialists only when they improve the task. A weekly check can finish without generating another campaign.
4. Use [reporting protocol](reporting-protocol.md) to show verified progress, blockers, unknowns and one next decision. Keep publication state separate from draft completion. Never manufacture performance improvements.
5. Offer a brief optional [feedback check](feedback-loop.md) after the useful output. A correction updates the relevant preference or fact immediately; a strategic idea stays a hypothesis until evaluated. Do not pester a user who declined feedback.
6. Save a compact [session journal](session-journal-template.md) with outputs, unresolved facts, next action and due review when local writes are available and appropriate. Preserve campaign state; without persistence, provide an explicit exportable unsaved handoff.
7. For requested recurrence use [scheduling protocol](scheduling-protocol.md). Schedule a concrete useful review, not a prompt to increase usage. Report a schedule as active only after registration and readback. A skill cannot wake itself up.

## What counts as useful engagement

First useful task completion, time to usable output, accepted/editable assets, resolved blockers, experiment decisions and return to a relevant next step. Count sessions only from explicit local journal records; unknown historical activity stays unknown. Do not chase messages, time spent or repeat opens as business outcomes. There is no cross-user dashboard or collection service in this package.

## Business boundaries and learning

All files are scoped to one selected business workspace. The coordinator owns durable state; specialists receive only the needed slice. Keep explicit preferences separate from observed outcomes, and keep personal preferences separate from customer evidence. Explain significant changed recommendations and retain contradictions. A successful campaign in one business is a hypothesis for another, not a transferable fact. An unavailable connector gets an import/draft path. Respect actual host tools and the user's established action authority.
