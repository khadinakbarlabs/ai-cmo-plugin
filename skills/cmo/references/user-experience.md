# Friendly entry points and progressive detail

Users can ask naturally. Translate these prompts to existing skills rather than adding commands:

| User intent | Result | Owner |
| --- | --- | --- |
| "Understand my business" | Short editable business brief, gaps, next action | Business Context |
| "What should we do next?" | One recommendation with evidence, effort and success signal | CMO |
| "Make it for me" | Actual reviewed copy/assets in usable form | Relevant production skill |
| "Show progress" | Visual/Markdown report with verified KPIs and next decision | Marketing Analytics |
| "Continue where we left off" | Reused assets and resumed valid task board | CMO |
| "Review this every week" | Concrete host schedule or clearly labeled draft handoff | Marketing Operations |
| "This missed the mark" | Corrected output and resolved feedback record | Business Context + relevant skill |

Begin with the result in plain language. Hide internal role IDs, schema details and score machinery unless they help the user decide. Use one primary recommendation and at most three useful next choices. Show uncertainty alongside the decision. Ask essential missing questions together after inspecting available context, and use known preferences instead of repetitive onboarding.

For a quick task deliver in one session; for a campaign show completed/remaining work; for an ongoing relationship start with what changed since the last useful session. Offer examples appropriate to the actual business and preferred language/voice. Preserve user's edits and distinguish suggested copy from approved copy. Avoid jargon, long checklists and compulsory ratings.

Do not invent a dashboard, app UI, persistent notification service or account connection. This is host conversation plus editable artifacts. Optional HTML reports are real files only when generated; the template is not a deployed dashboard. Return actual files/outputs and a clear next step. User trust and time saved take priority over usage volume.
